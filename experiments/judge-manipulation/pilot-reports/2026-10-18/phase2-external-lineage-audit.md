# External source lineage audit

I verified each pinned public file against its registry SHA-256, computed exact body and prompt hashes locally, and removed the temporary source files. This audit assigns no detector labels and retains no source text.

For School of Reward Hacks, the pinned CSV contains 105 candidate records across three task/metric families (44, 44, and 17). Every candidate record has both response fields, each candidate `user` value is unique, all 105 hack-field bodies and all 105 control-field bodies have distinct exact hashes, and no full body hash overlaps between roles. These facts support one source-record group per matched pair, with the attack and control kept together. They do not prove the source's reward-hack label equals Kev's judge-manipulation label.

There are six repeated exact 64-character response suffix hashes spanning 14 candidate response rows; no 128- or 256-character suffix repeats. I computed conservative transitive components by treating each source record as one node (attack and matched control stay together), unioning nodes whenever either response has the same repeated 64-character suffix hash, then taking connected components. The six repeated keys touch 12 source pairs and produce 98 components: 93 singletons, three pairs, and two triples (largest component: three). Thus 105 is only the pair-only upper bound; under this explicit suffix-linkage rule, the conditional cap is 98 groups. This remains a grouping cap rather than proof of independence because the source publishes no row IDs or generation seeds and suffix matching cannot find every possible shared lineage. Keep the three task/metric families as coverage and dependence slices; they are not automatically three lineage groups. If all pairs later pass target mapping, the suffix-linked cap is at most 98 positive and 98 negative rows at one row per component. This is far below the locked-test targets of 1,000 attacks and 2,000 negatives.

For NotInject, the three pinned Parquet files contain 339 rows, 113 per split. All 339 prompts and all 339 registered `(split, prompt, word_list, category)` group keys are unique; there are no repeated prompts across splits. They are benign user prompts, not submitted assistant responses, so they contribute zero eligible negative-response groups under the current detector scope. Keep all rows reserved and leave target eligibility unresolved. The exact English-eligible count also remains unknown; the category count of 84 Multilingual rows is not an exact language count.

The full file hashes, repeated suffix hashes, exact union rule, component counts, and capacity limits are recorded in [phase2-external-lineage-audit.json](phase2-external-lineage-audit.json).
